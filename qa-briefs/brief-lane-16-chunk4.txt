The complete feature inventory of the cockpit, built from the plan's own grading rubrics plus six features discovered during grading (webhook receiver panel, add-strategy form, emergency stop card, live session card, drill buttons, sign-in widget, settings page shell, home page shell, operator notes) and the AI gateway connection added when the AI integration was switched on. Every feature lists what 'working' means in UI-only terms and which of the eight test methods apply to it. Section V then exercises every feature through every applicable method.

### The eight test methods

- **RENDER** — Paints correctly: layout, no truncation/overlap/ellipsis, exact copy, badges/labels present.
- **LIVENESS** — Two-fetch: values advance, timestamps tick, cycles complete; distinguishes live from placeholder.
- **INTERACTION** — Safe clicks only: toggles off/on, check-now, filters, sorts, timezone toggle, modal open->cancel, arm->disarm, preview-only flows.
- **HONEST-STATES** — Empty and failure states read calmly and truthfully: outage copy (no silent buttons -- every action shows feedback), honest idle ('No run active'), stale labeling.
- **CROSSCHECK** — Arithmetic/consistency between panels: net=gross+fees, chips sum=total, alerts retained=alert rows, caps match across pages.
- **BOUNDARY** — Invalid/empty inputs: empty submits, bad names, out-of-range numbers -> plain-words validation errors, never silent no-ops.
- **PLAINWORDS** — No jargon, no raw engine strings, no stack traces/JSON/'undefined'/'NaN'; disclosures have What-happened/What-it-means/What-to-do-next; forbidden words never appear.
- **GUARD** — The dangerous action is gated: preview before fire, confirm before delete, PIN/approval for sealed groups, arm checkbox before preview; the tester verifies the gate WITHOUT crossing it.
